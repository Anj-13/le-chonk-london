## Blind pairwise judging (organiser's own criteria: technical depth, creativity,
usefulness, demo quality, alignment; equally weighted; pairwise not totals)

- A vs failover: A wins on creativity and demo theater (live emergent phenomenon
  vs a staged outage); failover wins on delivery certainty. This room's own record
  (a population-scale emergent sim won the global final) breaks the tie for A.
- A vs monoculture: A wins the demo (a spreading, controllable phenomenon beats
  falling bars); monoculture's own kill note ("the fix sounds too obvious") stands.
- A vs canary: canary wins commercial credibility (a board-reportable leak rate);
  A wins memorability and spectacle; for this practitioner panel, A.
- A vs verification budgets, overshoot gate, near-miss, common-cause: A wins on
  visual scale and sponsor-load-bearing; each challenger wins a sub-criterion
  (usefulness for budgets, build certainty for the gate) but loses the room.

## Verdict

**Primary: the incumbent (ChonkVid), now carrying one mechanism upgrade the blind
panel independently produced:** herd-immunity targeting (D-17). The vaccination beat
upgrades from a slider to a computed allocation: the minimal set of agents to harden
that provably breaks every cascade, chosen from the live contact topology. That is a
new causal mechanism (topology-aware allocation), not a stacked feature.

**Backup: functional-redundancy failover (D-23), with the monoculture audit's
correlated-failure table (D-22) folded in as one slide.** Pivot trigger: if the
epidemic dynamics are unstable by early afternoon, pivot without guilt; the
population, probe-stream and dashboard infrastructure is reusable and the failover's
delivery certainty is genuinely higher.

**Dissent preserved (do not average away):** the failover challenger is the safer
build and the more certain demo. If the team's morning run shows unstable dynamics
or the API budget is tighter than expected, the case for pivoting is real and
recorded here, not buried.
